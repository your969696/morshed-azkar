# إدارة المشروع | Project Management

## نظرة عامة

يتم إدارة المشروع باستخدام GitHub Projects و GitHub Issues.

---

## الأدوات المستخدمة

| الأداة | الاستخدام |
|--------|-----------|
| GitHub Issues | تتبع الأخطاء والميزات |
| GitHub Projects | إدارة المهام |
| GitHub Milestones | تتبع الإصدارات |
| GitHub Labels | تصنيف المشكلات |

---

## تصنيف المشكلات

### Labels

| Label | اللون | الوصف |
|-------|-------|-------|
| `bug` | 🔴 أحمر | خطأ في الكود |
| `enhancement` | 🟢 أخضر | تحسين ميزة موجودة |
| `feature` | 🔵 أزرق | ميزة جديدة |
| `documentation` | 🟡 أصفر | تحسين التوثيق |
| `help wanted` | 🟣 بنفسجي | يحتاج مساعدة |
| `good first issue` | 🟢 أخضر | مناسب للمبتدئين |
| `wontfix` | ⚫ رمادي | لن يتم إصلاحه |
| `duplicate` | 🟠 برتقالي | مكرر |

### Milestones

| Milestone | الوصف |
|-----------|-------|
| `v1.0.0` | الإصدار الأول |
| `v1.1.0` | تحسينات إضافية |
| `v1.2.0` | ميزات جديدة |
| `v2.0.0` | الإصدار الثاني |

---

## تدفق العمل

### 1. إنشاء Issue

- اكتب وصفاً واضحاً للمشكلة
- أضف Labels مناسبة
- أضف Milestone إن أمكن

### 2. مراجعة Issue

- يراجع المطورون Issue
- يطلبون معلومات إضافية إن أمكن
- يحددون الأولوية

### 3. تنفيذ Issue

- ينشئ المطور Branch جديد
- يكتب الكود المطلوب
- يختبر التغييرات

### 4. دمج التغييرات

- يفتح المطور Pull Request
- يراجع المطورون التغييرات
- يدمجون التغييرات في Main Branch

### 5. إصدار الإصدار الجديد

- يتم إنشاء إصدار جديد
- يتم تحديث الوثائق
- يتم إعلان الإصدار الجديد
